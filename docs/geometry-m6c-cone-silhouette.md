# Cone silhouette and user-authored diameter

Step 4A.1 preserves user-created diameter segments. A fixed world-space diameter
does not generally join the apparent cone silhouette contacts in an elevated
oblique projection. No diameter, labels, semantic entities, or camera changes
are generated by this correction.

For local radius r, height h and k=r/h, tangent azimuth theta satisfies:

- Orthographic, toward vector V: Vx cos(theta) + Vy sin(theta) + k Vz = 0.
- Perspective, local eye E: Ex cos(theta) + Ey sin(theta) + k Ez - r = 0.

The existing analytic calculation already satisfied these equations. The
rendering defect was that its exact contact angles were absent from the
uniformly sampled base circumference and fill. Cone rendering now inserts those
angles into the shared rim/fill samples. Facet facing tests use each resulting
interval's actual midpoint and half-angle. Projection/visibility retains the
actual nonuniform angles when splitting visible and hidden rim arcs.

In perspective, an eye at apex height gives antipodal contacts, so a diameter
joining them is mathematically valid. In elevated orthographic views the true
contact chord is generally not a diameter; forcing coincidence would distort
the geometry. Cylinder sampling and semantic ownership are unchanged.

`node tests/cone_silhouette_browser.mjs`. The latter uses real headless Microsoft
Edge with the production editor and saved-camera SVG in an isolated Vite
fixture; it does not claim a PostgreSQL save/reload browser acceptance run.
